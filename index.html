Updated 28 October 2026 · source a0250e9 · main.

Every game is one EUF-CMA experiment, Model.EufCma.game, at a scheme and an attacker model (ordinary oracle programs, or algebraic attackers), within a declared query allowance from which the reduction derives its budgets and loss factors. Everything a statement's meaning depends on is in Signatures/; the proofs, the executed reductions and their resource accounting are in Proofs/, and an audit test keeps that boundary.

The public games for all four schemes now show the experiment directly: generate a key, run the attacker with adaptive oracle access, hash the proposed forgery, and check the verification equation and freshness. Named state fields, requests and results replace tuple positions and nested query encodings.

    AGM with DLog reductions; ordinary ROM with a co-CDH reduction. Caliper concrete and asymptotic proofs are complete for both routes.

    Caliper concrete and asymptotic AGM proofs are complete, retaining the target-topic degree rule.

    Caliper concrete and asymptotic AGM proofs are complete. Fresh-collision probability remains an additional term.

  • Schnorr

    AGM: Caliper concrete and asymptotic proofs are complete.

    ROM: Caliper concrete and asymptotic proofs are complete for both the full-field and nonzero-nonce routes.

    Game · Statement · AGM (asymptotic · equality) · ROM (asymptotic · equality) · nonzero-nonce ROM (asymptotic · equality)

  • Synchronized Pointcheval–Sanders

    AGM proof with three explicit (1,1)-DLog solvers: the challenge as either key or in the period hashes. Certified co-signer keys, one honest signature per period, finite periods (the solvers sample a hash table). Caliper concrete and asymptotic AGM proofs are complete for any period type: the attacker's caller is wrapped for two weighted schemes with the other key known, giving four executed solvers (4·εDL + 2/p). The same wrapping is proved in the general PolyFun backend: the attacker's realized caller is wrapped at every known key, each sampled solver's advantage is an average of in-budget solvers, and the asymptotic corollary picks the best key per security parameter.

    Game · Statement · AGM (solvers · equality) · Caliper (budgeted · asymptotic · model · wrapper · periods)

An algebraic group model for VCVio

The AGM results above rest on agm-lean, a separate Apache-2.0 library that adds the algebraic group model to Lean 4 and VCVio. Other VCVio games can use it.

An algebraic adversary must explain every group element it sends as a combination of group elements it has already received. Having received g, X and Y, an adversary that sends a group element Z, in a query or in its final answer, also gives coefficients a, b, c with:

Z=a·g+b·X+c·Y

The library prescribes no game or oracle. Oracle replies need no explanation; they join the list of received inputs. The adversary supplies a Lean proof that its explanations hold on every possible reply path, and the library proves that running it yields valid explanations over the inputs it actually received.

Several groups can share one scalar field, as the two source groups of a pairing do. Each group element is explained only from inputs of its own group.

Key definitions

  • IsAlgebraic

    The explanation rule, required on every possible reply path.

  • Adversary

    A VCVio program paired with its proof of that rule.

  • Adversary.run

    Runs it through VCVio’s simulateQ, tracking each group’s received inputs.

  • Adversary.run_valid

    Every final explanation is valid over the inputs actually received.

The model does not bound running time or explain elements of a pairing’s target group. Games must keep every group element in the tracked group lists; group elements hidden in plain data go untracked. It starts from Fuchsbauer, Kiltz and Loss, The Algebraic Group Model and its Applications, Section 2.1.
